# Рабочие инструкции

Этот документ задает рабочий порядок для разработчика, ревьюера и AI-агента. Он не заменяет
[Picboard Frontend Style Guide](./style_guide_full.md): основной источник правил всегда там.

## Роль

Работайте как senior frontend engineer: держите код простым, предсказуемым и поддерживаемым.
Решения должны быть понятны junior/middle разработчику без дополнительного устного контекста.

Для AI-агента этот документ работает как краткий skill: сначала прочитать источник правды,
затем выбрать релевантный раздел, внести минимальное изменение и явно написать, что проверено.

## Перед изменениями

- Прочитайте `docs/style_guide_full.md` и релевантные документы из `docs/`.
- Сначала изучите существующий код, конфиги и локальные conventions модуля.
- Для Next.js API и framework conventions проверьте `node_modules/next/dist/docs/`.
- Следуйте текущей архитектуре проекта.
- Не добавляйте зависимости без явной необходимости.
- Не делайте unrelated refactoring.
- Если решение неочевидное, кратко зафиксируйте trade-off перед изменением.

## Во время изменений

- Делайте минимальные точечные изменения.
- Используйте TypeScript без `any`, если есть безопасная альтернатива.
- Предпочитайте named exports.
- Не используйте `React.FC`.
- Не добавляйте formatting rules в ESLint.
- Не создавайте legacy `.eslintrc`.
- Не меняйте public API модуля без необходимости.
- Не смешивайте feature, refactor и formatting в одной задаче.

## После изменений

Проверьте результат:

```bash
pnpm check
```

Если `pnpm check` слишком дорогой для маленькой правки, запустите релевантную часть и явно
напишите, что именно было проверено.

## Summary или PR

- Пишите кратко и по делу.
- Показывайте diff или краткое summary изменений.
- Отдельно отмечайте риски, edge cases и то, что не удалось проверить.
- Если инструкция конфликтует с кодом, сначала разберитесь в причине, затем предложите минимальную
  правку документа или кода.
