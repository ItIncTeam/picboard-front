Feature-Sliced Design (FSD) — Архитектура проекта

📁 Общая структура src/

src/
│
├── app/ # Инициализация приложения
├── shared/ # Переиспользуемая инфраструктура
├── entities/ # Бизнес-сущности
├── features/ # Пользовательские действия
├── widgets/ # Крупные UI-блоки
└── views/ # Страницы (композиция UI)

🚀 app/ — инициализация приложения

Отвечает только за инфраструктурный слой приложения.

Основные зоны ответственности:
routing (роутинг)
layouts (макеты страниц)
route groups (группы маршрутов)
locale routing (i18n)
metadata (SEO, head)
error / loading pages

❗ Не содержит бизнес-логики и переиспользуемого UI.

🧩 shared/ — переиспользуемая инфраструктура

Не содержит бизнес-логики. Только универсальные инструменты.

Структура:

shared/
│
├── ui/
├── lib/
├── api/
├── hooks/
├── constants/
├── styles/
└── assets/

📦 shared/ui — UI Kit

Переиспользуемые «глупые» компоненты интерфейса:

Button
Input
Modal
Select
Checkbox
Typography

📌 Без бизнес-логики

🧠 shared/lib — утилиты

Чистые функции и helpers:

debounce
formatDate
validators

🌐 shared/api — API слой
axios instance
RTK Query base setup
interceptors (auth, error handling)

⚙️ shared/constants — константы
глобальные ключи
enum значения
конфиги

🎨 shared/styles — дизайн система
colors.css
reset.css
typography.css
variables.css

🖼 shared/assets — статические ресурсы
изображения
иконки
шрифты

🧱 entities/ — бизнес-сущности

Описание предметной области.

Примеры:
user
post
message
payment

📌 Правило:

entities не зависят от features
описывают данные и базовую бизнес-логику

⚡ features/ — действия пользователя

Конкретные пользовательские сценарии.

Примеры:
sign-in
create-post
like-post
follow-user
send-message

📌 Feature = одно действие пользователя

🧩 widgets/ — крупные UI блоки

Композиция entities + features в готовые блоки интерфейса.

Примеры:
sidebar
header
messenger-chat
posts-feed
profile-header

📌 Используются внутри страниц

📄 views/ — страницы приложения

Собирают всё приложение в готовые страницы.

Используют:
widgets
features
entities
Примеры:
feed-page
profile-page

📌 Это финальный слой перед routing

🧠 Главные принципы FSD
❌ нельзя нарушать слои
❌ entities не зависят от features
❌ shared не знает о бизнесе
❌ нижние слои не импортируют верхние
✅ зависимости идут сверху вниз
✅ каждый слой имеет одну ответственность

📌 Коротко
app — инициализация и роутинг
shared — переиспользуемое общее
entities — бизнес-данные
features — действия пользователя
widgets — UI блоки
views — страницы

Диаграмма зависимостей FSD:

        │            entities             │
