# Project Brief

Этот документ фиксирует продуктовый контекст Picboard: цели, границы MVP/первого релиза,
допущения, ограничения и процесс поставки. Он помогает команде и AI-агенту принимать решения в
рамках утвержденного scope.

Источник инженерных правил остается в [Picboard Frontend Style Guide](./style_guide_full.md).

## Цели проекта

### Бизнес-цели

- Создать современную социальную web-платформу для публикации и взаимодействия с мультимедийным
  контентом.
- Повысить вовлеченность пользователей через персонализированную ленту, подписки, лайки,
  комментарии и личные сообщения.
- Обеспечить возможность монетизации через систему платных подписок.
- Подготовить масштабируемую архитектуру для дальнейшего развития продукта.
- Дать администраторам инструменты управления пользователями и базового контроля активности
  платформы.

### Продуктовые цели

- Реализовать удобную и безопасную аутентификацию пользователей.
- Дать пользователям возможность создавать, редактировать и удалять мультимедийные посты,
  добавлять подписи и хэштеги.
- Реализовать социальные механики: лайки, комментарии, подписки, репосты и личные чаты.
- Обеспечить real-time уведомления о лайках, репостах, подписках, комментариях, платежах и личных
  сообщениях.
- Реализовать управление платными подписками и тарифами с дополнительными функциями.
- Открыть часть функционала для неавторизованных пользователей: просмотр популярных пользователей
  и постов.
- Предоставить поиск пользователей и понятную навигацию по платформе.

### Технические цели

- Разработать адаптивную web-платформу.
- Обеспечить безопасное хранение пользовательских данных и аутентификационной информации.
- Интегрировать платежную систему для подписок.
- Реализовать real-time уведомления и обмен сообщениями.
- Сохранить возможность дальнейшего масштабирования и поддержки проекта.

## Scope

### In Scope

#### 1. Аутентификация и авторизация

- Регистрация пользователей.
- Авторизация пользователей.
- Выход из системы.
- Запоминание данных пользователя для быстрого входа.
- Восстановление пароля.
- Базовая защита пользовательских данных.
- Управление пользовательской сессией.

#### 2. Управление профилем

- Создание профиля.
- Редактирование данных профиля.
- Загрузка фотографии профиля.
- Добавление биографии.
- Просмотр истории публикаций пользователя.

#### 3. Публикации

- Создание постов с изображениями.
- Добавление подписей и хэштегов.
- Просмотр публикаций.
- Редактирование публикаций.
- Удаление публикаций.

#### 4. Лента и публичный контент

- Персонализированная лента пользователя.
- Просмотр популярных публикаций.
- Просмотр популярных пользователей.
- Публичная страница для неавторизованных пользователей.

#### 5. Социальные взаимодействия

- Лайки публикаций.
- Комментарии к публикациям.
- Репосты публикаций.
- Подписка и отписка от пользователей.
- Просмотр подписчиков и подписок.

#### 6. Поиск

- Поиск пользователей.
- Отображение найденных профилей.

#### 7. Личные сообщения

- Отправка и получение личных сообщений.
- Просмотр истории переписки.

#### 8. Уведомления

- Real-time уведомления о новых подписчиках.
- Real-time уведомления о платежах.
- Real-time уведомления о взаимодействиях с контентом.

#### 9. Платные подписки

- Выбор тарифного плана.
- Оформление подписки.
- Интеграция платежной системы.
- Ограничение или открытие premium-функций.

#### 10. Административная панель

- Просмотр пользователей.
- Управление пользовательскими аккаунтами.
- Базовая модерация пользователей.

#### 11. Техническая реализация

- Frontend-разработка.
- Backend-разработка.
- Проектирование базы данных.
- API-интеграции.
- Базовое тестирование функционала.
- Базовая техническая документация.

### Out Of Scope

#### 1. Мобильные приложения

- Нативные iOS и Android приложения.
- Поддержка мобильных SDK.

#### 2. Расширенная модерация контента

- AI-модерация изображений и текста.
- Автоматическое выявление запрещенного контента.
- Система жалоб и пользовательская поддержка.

#### 3. Продвинутые социальные функции

- Stories, Reels, Shorts.
- Видеостриминг.
- Группы и сообщества.
- Голосовые и видеозвонки.
- Геолокация в постах.

#### 4. Продвинутая аналитика

- Поведенческая аналитика пользователей.
- Рекомендательные ML-алгоритмы.

#### 5. Маркетинговые инструменты

- Рекламный кабинет.
- Продвижение постов.
- Email-маркетинг.
- Push-маркетинг вне платформы.

#### 6. Интеграции третьих сторон

- Интеграции с внешними CRM.
- Социальные логины: Google, Facebook и другие.
- Интеграции с внешними аналитическими системами.

Платежная интеграция остается in scope.

#### 7. Повышенные нефункциональные требования

- Enterprise high-load архитектура.
- Multi-region deployment.
- SLA и 24/7 support.
- Disaster Recovery инфраструктура.

#### 8. Юридические и операционные задачи

- Подготовка юридической документации.
- GDPR или Compliance аудит.
- Контентная поддержка платформы.
- Операционная модерация пользователей после релиза.

#### 9. Дополнительные работы вне первоначальной оценки

- Функциональность, не описанная в утвержденном scope.
- Изменения требований после согласования scope.
- Поддержка после гарантийного периода.

## Допущения

### Бизнес-допущения

- Заказчик своевременно дает обратную связь и участвует в согласовании требований.
- Ключевые стейкхолдеры доступны для принятия решений.
- Описанные требования достаточны для старта разработки.

### Технические допущения

- Инфраструктура для размещения проекта: серверы, cloud services, домены и доступы,
  предоставляется заказчиком или согласуется отдельно.
- Платежный провайдер предоставляет стабильное API и необходимую документацию.
- Сторонние сервисы и библиотеки доступны без ограничений на территории эксплуатации продукта.
- Real-time функциональность может быть реализована через WebSocket или аналогичную технологию.
- Для MVP/первого релиза допускается базовый уровень отказоустойчивости.

### Организационные допущения

- Команда проекта укомплектована необходимыми специалистами на протяжении проекта.
- Работа выполняется по модели Time & Materials.
- Коммуникация идет через согласованные каналы: Jira, Slack, Telegram, Email или другие.
- Проект реализуется в рамках согласованного бюджета и первоначальной оценки в 4000 man-hours.
- Приемка функционала выполняется поэтапно после согласованных milestones или спринтов.

## Ограничения

### Временные ограничения

- Срок реализации проекта: 6 месяцев.
- Разработка должна укладываться в согласованные roadmap и milestones.
- Задержки согласований со стороны заказчика могут влиять на сроки.

### Бюджетные ограничения

- Проект ограничен первоначальной оценкой в 4000 man-hours.
- Дополнительные работы вне утвержденного scope оцениваются отдельно.
- Увеличение команды или расширение функционала может повлиять на бюджет.

### Технические ограничения

- Разработка выполняется в рамках web-платформы.
- Нативные мобильные приложения не входят в текущий scope.
- Технологический стек определяется технической командой и утверждается заказчиком.
- Интеграции со сторонними системами ограничены платежным провайдером и согласованными сервисами.
- Производительность системы рассчитывается на предполагаемую нагрузку MVP/первого релиза.

### Функциональные ограничения

- Реализуется только функциональность из утвержденного scope.
- Стриминг, stories, AI-рекомендации и другие продвинутые функции социальной сети не входят в
  текущую реализацию.
- Административная панель включает только базовое управление пользователями.

### Ресурсные ограничения

- Доступность ключевых специалистов заказчика зависит от их внутренней загрузки.
- Количество участников команды фиксируется исходя из бюджета и сроков.
- Проект зависит от своевременного предоставления доступов, API-ключей и необходимых материалов.

### Организационные ограничения

- Все изменения требований после утверждения scope проходят formal change management process.
- Приоритеты задач определяются совместно заказчиком и project management командой.
- Архитектурные и технические решения принимаются в рамках согласованных стандартов проекта.

## Жизненный цикл и методология

### Подход

Проект ведется по гибридной модели Hybrid: Scrum + Waterfall.

Waterfall используется для верхнеуровневого планирования, согласования архитектуры, milestones и
контрольных точек. Scrum используется на этапе разработки для управления задачами, итеративной
поставки и регулярной демонстрации результата.

Выбор подхода связан с фиксированным сроком 6 месяцев, предварительно определенным scope,
необходимостью регулярной поставки функционала, возможными уточнениями требований и высокой
вовлеченностью технических специалистов заказчика.

### Scrum-практики

- Спринт длится 2 недели.
- Sprint Planning.
- Daily Stand-up meetings.
- Sprint Review / Demo.
- Sprint Retrospective.
- Backlog refinement.

### Waterfall-элементы

- Фиксация high-level scope проекта.
- Предварительное архитектурное проектирование.
- Фиксированные milestones.
- Этапная приемка результатов.
- Управление изменениями через change request process.

## Этапы проекта

### 1. Инициация и Discovery

Продолжительность: около 1 недели.

Основные работы:

- Анализ бизнес-требований.
- Уточнение функционального scope.
- Формирование backlog.
- Определение архитектуры решения.
- Планирование roadmap.
- Подготовка проектной документации.

Результат:

- Утвержденный scope.
- Product backlog.
- Архитектурное решение.
- План реализации проекта.

### 2. Проектирование и подготовка инфраструктуры

Продолжительность: около 2 недель.

Основные работы:

- Проектирование базы данных.
- Подготовка CI/CD.
- Настройка environments.
- Подготовка дизайн-системы и UI guideline.
- Настройка репозиториев и процессов разработки.

Результат:

- Готовая техническая инфраструктура.
- Базовая архитектура frontend/backend.
- Development environments.

### 3. Основная разработка

Продолжительность: около 14-16 недель.

Основные модули:

- Authentication.
- User Profile.
- Posts.
- Feed.
- Search.
- Subscriptions.
- Notifications.
- Messaging.
- Admin Panel.
- Payment Integration.

Формат:

- Scrum-спринты по 2 недели.
- Поэтапная поставка функционала.
- Регулярные demo заказчику.

Результат:

- Готовый функционал согласно backlog.

### 4. Тестирование и стабилизация

Продолжительность: около 3 недель.

Основные работы:

- End-to-end testing.
- Исправление дефектов.
- Проверка производительности.
- Проверка безопасности.
- Финальная интеграция модулей.

Результат:

- Release Candidate.
- Стабилизированная версия продукта.

### 5. Release и запуск проекта

Продолжительность: около 1 недели.

Основные работы:

- Подготовка release documentation.
- Передача проекта заказчику.
- Финальная приемка.

Результат:

- Production release.
